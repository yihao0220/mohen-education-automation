# 墨痕教育项目规则库

渐进式披露：**先判断当前是哪个项目 → 只读对应的一个 reference 文件 → 需要通用规则时再读通用文件。**
不要一次性把 `references/` 全读进来，那正是这个 skill 存在的原因。

上面每个项目文件只写**该项目独有**的部分。做具体项目时通常需要读两个文件：通用 + 该项目。

## 接手新项目的默认动作

1. 读 [references/通用录入规则.md](references/通用录入规则.md)。
2. 找最接近的既有项目，读它的 reference，判断能不能复用覆盖层而不是新写引擎。
3. 查 `../墨痕教育-记忆库/模块问题/跨模块项目/INDEX.md` 有无同类总归档。
4. 学科差异优先进 `subject_overlay`，不要改全局默认，不要在 `core_parser.py` 里加临时 `if/else`。
5. 历史经验只作风险提示；与当前代码冲突时，以当前代码和真实样本验证为准。

## 归档义务

新项目开发完成后要产出两类记录，走 skill `mohen-archive-check`：
项目内 `问题归档/` 存代码证据，`../墨痕教育-记忆库/` 存可复用摘要。
本 skill 的 `references/` 只在规则**稳定成型**后更新，不要把每次调试细节写进来。
