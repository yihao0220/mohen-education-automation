# 通用录入规则（跨学科、跨学校）

来自 2026-04 起的连续实战。接新项目时默认按这套执行，不要从零试错。

## 题目录入（F1）

- **材料题按题号范围截断。** 出现 `完成3-5小题`、`据图完成6-8小题` 这类明确范围时，只吞并范围内小题，遇到下一个超范围题号立刻停止。
- **主观大题不按小问拆。** `13. ……回答下列问题。(1)…(5)…` 默认整体作为一道题录入。
- **表格题统一保留原生表格。** 所有学科、学校、项目一致：直接整块框选题干、表格和选项后按 F1，不再转纯文本、不再创建临时文档。
- **表格内的小数、百分数、数据单元不能当题号起点。** 日志里"发现题号数量"和"准备录入题数"明显不一致时，优先排查表格元数据是否丢失。
- **题内板块标题不是截断边界。** `【独特的自然环境】`、`【一粒种子的远征】` 这类默认视为题内结构。
- **图表题优先保证边界。** 题干和选项之间夹图片或表格时，先保证整题边界正确，再处理展示样式。
- **低置信度题后台标记，不中断录入。** 不要每题停下等用户回车。
- **风险提示必须说中文。** 不要把 `image_related_question`、`sparse_options` 这类内部码直接抛给用户。

## 题号前缀

- `G1.`、`C2.`、`Y6.`、`【G】1.` 这类前缀题号**不做全局通用规则**，放具体学科覆盖层或白名单文档。
- 单批卷子的个例，就按该批文档白名单保留，不要为一个案例污染全局题目录入规则。
- 但如果某类装饰题号在一个项目里**反复出现且不是单卷个例**（如 `★11.`、WPS 文本层里的 `/11.`），应升级为共享前缀兼容，不要继续靠白名单打补丁。

## 科目识别

- 文件名不含学科名时，要结合正文关键词和题型特征做内容嗅探，避免文科卷误判到理科。

## 答案清洗

- **正文优先。** 原始答案同时有"表格答案"和"正文答案+解析"时，正文优先，表格只补正文缺失的题号，不重复摘录。
- **不保留装饰性标题。** 试卷标题、题型标题、红色说明性抬头默认不进清洗结果。
- **标准化压力留在清洗阶段。** 连写答案、表格答案、材料题小问答案都在清洗阶段处理完，不要把识别压力甩给 `answer_input.py`。
- **空解析要显式补占位。** 缺少解析的答案块会被系统阻断；业务允许空解析时，补 `解析：` 占位，不要让块结构悬空。

## 答案录入（F2/F3/F4）

- **不是所有 `(1)(2)(3)` 都拆 F4。** 先确认插件该题型实际是单答案框还是多答案框；只有一个答案框时改为整段 F2，并把该策略固化成项目级或文档级规则。
- **`①②③…` 是答案内部列点，不是 F4 标志。** 只有明确的 `(1)(2)…` / `（1）（2）…` 小问，或完整阅读题分组，才进 F4 流程。
- **录入坐标必须保留原文段落位置。** 过滤标题和空段只能改变语义载荷，不能压缩 F2/F3/F4 使用的段落坐标。

## 数学类答案

- 能稳定转成纯文本的内容留在答案区；公式对象、富文本风险、会乱码的内容转入解析区承载，不要强塞进答案框。
- 斜体 Unicode 字母（`𝑥 / 𝑦 / 𝑏 / 𝑘`）先在清洗阶段归一化成普通 `x / y / b / k`，再判断是否需要转解析。不要把这类字符误判成公式对象。
- 富文本模板清洗后若要保公式，默认跳过纯文本题答重写链路。一旦误走重写链路，优先怀疑公式对象被写没，而不是先怀疑模板没命中。

## 解析续行识别

收到用户的 docx 样本后，主动检查解析块里是否存在 `①②③④`、`A：B：C：D：`、`故本题选X。` 等续行格式，并验证清洗逻辑能完整收集这些续行，而不是只收 `【解析】` 首行。

## 产物与工作区

- 开发辅助产物（`_审核清单.md`、调试摘要、归档补充文档）放项目目录或长期目录，**不要放进用户的题目源目录**。
- P1b 的 PDF、页面 PNG、页面/视觉/校准 JSON 及 `BatchSourceManifest.json` 必须放在原题和 Git 仓库之外，不得提交业务路径或真实文档派生事实。
- 每份清洗答案只保留一个最终版 `*_已清洗.docx`，中间版本及时清理。
- 面向用户实际录入的目录只保留「原题 / 原答案 / 最终清洗版」，不混入开发过程文件。
- 新样本文档放既有样本目录，不散落到仓库根目录。

## 验证习惯

- 每次改规则至少两层验证：离线测试覆盖核心逻辑 + 真实样本文档定向复核。
- 优先补失败用例，再修代码。
- 测试结束清理临时 docx、临时审核清单、临时输出目录。
