# V2统一交接单与稳定身份

## L1 摘要

- 模块：共享内核 / 题目录入影子旁路
- 日期：2026-08-20
- 状态：第一部分离线实现完成；生产入口未接管
- 结论：新增版本化 V2 交接单、稳定身份、来源三分区、JSON Schema、黄金 JSON、旧 `QuestionUnit` 影子适配和差异报告。新链固定 `mode=shadow`、`production_execution_enabled=false`、`keypress_count=0`，未修改任何 F1/F2/F3/F4 生产入口。

## L2 现象与根因

### 现象

- 旧 `question_id` 可能只是题号，同一文档中两篇材料都出现第 1 题时无法唯一标识题目实例。
- `QuestionUnit.source_span` 只能表示连续范围，无法表达“保留前后正文、排除中间标题”。
- paragraph、table、media、formula 没有统一引用格式；规则版本、来源证据和生成器版本也没有共同交接字段。
- 题目、答案和后续动作如果继续只靠题号或重新扫描对齐，模块之间无法独立测试和局部回退。

### 根因

- 旧共享模型是第一阶段结果层，目标是兼容三入口，并未承担完整来源契约和稳定实例身份。
- 现有 `DocumentProfile` / `ActionPlan` 已有 SHA256 与部分 `source_ref`，但其 schema 不适合作为题目、答案和动作共同身份层。
- 生产链仍在使用旧对象，因此本次不能原地升级旧 schema 或直接替换消费者。

## L3 改动点

### 纯契约层

- 新增 `shared_core/contracts_v2.py`：
  - `SourceRef`：记录源文件 SHA256、原生类型、原生 ID、出现序号和文本锚点；
  - `StableUnitId`：由文档 SHA256、unit kind、occurrence 和原标签确定性派生；
  - `DecisionEvidence`：记录规则、原因、来源引用、置信度和生成器版本；
  - `SourcePartition`：显式保存 `included_refs`、`excluded_refs`、`unknown_refs`；
  - `QuestionUnitV2` 与 `CanonicalAnswerUnit`：严格序列化、反序列化和稳定 JSON 字节；
  - `build_source_partition()`：对缺失、范围外、重复和交叉分类全部阻断。
- 新增两份 Draft 2020-12 JSON Schema：
  - `shared_core/schemas/question-unit-v2.schema.json`；
  - `shared_core/schemas/canonical-answer-unit-v2.schema.json`。

### 影子适配层

- 新增 `shared_core/contract_v2_shadow.py`：
  - 只读接收现有 `DocNode` / `QuestionUnit`；
  - 同题号按文档出现次序生成不同稳定 ID；
  - 同一原生段落拆成多个虚拟节点时保留 occurrence；
  - media 元数据保持独立 `native_kind=media`，不伪装成 paragraph；
  - 输出 V2 契约 bundle 与逐题差异报告；
  - 始终附带 `SHADOW_CONTRACT_NOT_PRODUCTION` 阻断项。
- 新增 `tools/build_question_contract_v2_shadow.py`：
  - 影子产物必须写到源目录之外；
  - 运行前后核对原题 SHA256；
  - 控制台明确按键数为 0，未改变生产入口。

### 黄金样本与实施计划

- 新增 `test_contracts_v2/contract_fixture_golden.json`，固定题目/答案契约的规范字节。
- 新增文件级计划 `docs/plans/2026-08-20-contract-v2-stable-identity-implementation-plan.md`。
- 没有修改 `shared_core/models.py`、`document_preflight.py`、`answer_input.py`、`core_parser.py` 或任何 `wps_helper.py`。

## L4 测试样例与命令

### 失败优先

- 在实现前分别运行契约测试和影子测试，先确认因模块不存在而失败，再补最小实现。

### 核心样例

- 同一文档两篇材料各有第 1 题，两个 `StableUnitId.value` 不同；
- `材料正文 → 中间标题 → 题干` 中，正文和题干 included、标题 excluded，JSON 往返后不变；
- paragraph/table/media/formula 四种引用键互不混淆；
- expected scope 中漏分一个节点、同一节点重复分类、加入范围外节点均阻断；
- 公式可进入 `unknown_refs` 与 `rich_content_refs`，`CanonicalAnswerUnit` 不保存 F2/F4 决策；
- 同一输入重复生成的规范 JSON 字节与黄金 JSON 一致；
- AST 检查确认契约与影子模块不导入 WPS、`win32com`、`pyautogui` 或生产执行模块。

### 定向和相邻回归

```bash
python -m pytest -q -rs \
  test_contracts_v2.py \
  test_contract_v2_shadow.py \
  test_document_preflight.py \
  test_shared_core_flow.py
```

- 首轮未安装 Docling 时结果为 `30 passed, 1 skipped`。
- 使用 Python 3.12 隔离环境安装 `docling==2.113.0` 后，Docling 单项对照为 `1 passed`，整组复跑结果为 `31 passed`，无 skip。
- 系统 Python 3.9.6 不满足 Docling 2.113.0 的 `Python >= 3.10` 要求；不能通过降级 Docling 冒充锁定版本验证。

  shared_core/contracts_v2.py \

  tools/build_question_contract_v2_shadow.py \
  test_contracts_v2.py \
  test_contract_v2_shadow.py

- 结果：退出码 0，无语法错误。

### 实际 CLI 只读复核

- 使用临时 DOCX 构造两次第 1 题；CLI 输出 `unit_count=2`、两个不同稳定 ID、`mode=shadow`、`keypress_count=0`。
- 原题运行前后 SHA256 均为 `85815241e8d77139a4270c120a669f81ac2a0283f1ab675c2366adbe07b8204b`。
- 两份 JSON 可按 UTF-8 读回，无 U+FFFD 替换字符。
- 临时 DOCX、JSON 和临时依赖目录已在收尾阶段清理。

### 仓库全量 pytest 边界

- `pytest -q` 仍会收集历史离线脚本；`答案录入/test_parse_logic.py` 和 `答案录入/test_subq_split.py` 在模块导入时替换 `sys.stdout`，导致 pytest 会话结束时出现 `ValueError: I/O operation on closed file`。
- 这是既有全量收集方式问题，本次未修改这些脚本，也不能把该次全量尝试记为通过；本次有效证据是上面的 31 项定向/相邻回归。

## L5 结论、边界与下次入口

### 已证明

- V2 交接单能无歧义表达重复题号身份、非连续来源和四类原生引用；
- 同一输入可生成稳定、可往返、可黄金回归的 JSON；
- 来源静默丢失、交叉分类和范围外引用会被契约构造器阻断；
- 旧 `QuestionUnit` 可在不修改生产入口的情况下生成 V2 影子对象和差异报告；
- 契约层与 WPS 执行依赖隔离。

### 未证明

- 不证明旧题块判断本身正确，也未让 `QuestionUnitV2` 接管生产题块；
- 现有 `DocNode` 影子适配只接收 metadata 已暴露的 table/media/formula；未暴露对象不能冒充全源覆盖；
- 不证明答案提取、题答映射、F1/F2/F3/F4 ActionPlan、WPS Range 或真实插件录入正确；
- 未进行 Windows/WPS 测试，因为本部分明确不连接执行层。

### 回退

- 生产入口没有导入新模块；停止运行影子 CLI 即回到原状态。
- 新文件使用独立 schema 和文件名，不覆盖旧 `DocumentProfile.json`、`ActionPlan.json` 或审核状态。
