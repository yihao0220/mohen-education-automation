# 莞美高二地理材料题答案兼容 F4 分段排版

## L1 摘要

- 模块：题目拆分 + 答案格式转换 + 答案录入预演
- 日期：2026-08-01
- 状态：本地开发、真实执行函数无按键验证和 Windows 兼容包检查通过；Windows WPS 生产验证与本轮 Git 提交待完成
- 结论：莞美高二地理材料题统一输出为“一个顶层题号 → 每个小问答案各占一段 → 一个合并解析段”。这次不修改共享解析器或 `答案录入/answer_input.py`，而是在专项答案渲染层生成执行器已经能稳定识别的排版。

## L2 当前功能链与问题证据

当前链路是：

```text
总题目只读拆分
→ 课时 / 微点 / 章末答案匹配
→ 材料题原题号分组并重新编号
→ 生成已清洗答案 DOCX
→ 答案录入执行层剥离顶层题号
→ 每个小问按 F4，合并解析按一次 F3
```

原先把材料题答案写成同一行：

```text
1．（1）B（2）B
解析：（1）第一小题解析（2）第二小题解析
```

共享 DOCX 解析可以识别两个小问，但真实 WPS 执行入口会先调用 `strip_input_question_prefix()`。该函数把同一行的 `1．（1）` 一起当作题号前缀剥离，留下 `B（2）B`；随后 `find_subquestion_matches()` 只能看到后一个标记，最终只按一次 F4，并把 `B（2）B` 整段录入第一个答案框。这与用户报告的现象完全一致。

因此，“共享解析结果有两个答案项”不能证明真实执行选区也有两个 F4；必须额外经过答案录入最终选区函数验证。

## L3 最终方案与替代方案

最终清洗排版：

```text
1．
（1）B
（2）B
解析：（1）第一小题解析（2）第二小题解析
```

- 材料题如“阅读材料，回答 1、2 小题”，把原 1、2 题合并为一个顶层题；原答案分别改标为 `（1）`、`（2）`。
- 下一组如原 3、4 题，重新编号为顶层第 2 题，内部仍按 `（1）`、`（2）`。
- 每个小问答案独立成段，执行层逐段得到 `B`、`B` 两个 F4 载荷。
- 同组各小问解析保留在一个 `解析：` 段中，一次 F3 录入；不拆成两个解析框。

曾考虑并实际试验过两种替代方案：

1. 修改共享解析器，使同行复合题号在更多场景下保留首个小问；影响多个学科和历史模板，且不能单独解决真实执行层再次剥离前缀的问题，已回退。
2. 修改 `答案录入/answer_input.py` 的前缀剥离和小问查找；会扩大共享执行层风险。当前只改专项输出排版即可满足同一目标，因此未采用。

## L5 生产验收与下次排查入口

Windows WPS 至少抽查一组双选择材料题、一组跨原题号重新编号的材料题和一组带图片/公式的答案：

- 每个小问只触发一次 F4；
- 第一个框只收到第一个答案，第二个框只收到第二个答案；
- 顶层题号和 `（1）（2）` 标签不进入答案框；
- 两小问解析一起进入一次 F3；
- 题目 F1 保留题图、表格、公式与原排版。

若再次出现 `B（2）B` 整段进入一个框：

1. 先回读已清洗 DOCX，确认顶层题号与每个小问确实是独立段落；
2. 再记录 `strip_input_question_prefix()` 的输出；
3. 最后比较 `find_subquestion_matches()` 的标记和每个最终 WPS Range 文本；
4. 不要只看 `build_answer_units_from_docx()` 的逻辑答案项数量。
